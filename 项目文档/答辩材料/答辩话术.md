## 二、评委高频 QA（10 题 + 标准答法，每题 30 秒内答完）

### 🔴 Q1：为什么选择 FastAPI 而不是原来的 Flask？（异步硬门槛）
> **答**：因为评分文档明确写了「不使用异步编程接口拿不到本次作业分数」。Flask 基于 WSGI 同步模型，会阻塞事件循环；FastAPI 基于 ASGI，所有路由 `async def` + `asyncio.to_thread` 包装 SQLite 和判题这种同步 IO，加上 `asyncio.create_task` 做后台判题——**既满足了硬门槛要求，又实际提升了并发能力**（后台判题不阻塞前端其他请求）。

### 🔴 Q2：三元权限模型具体怎么实现的？403/200 的 audit_logs 记录策略？
> **答**：查 `/submissions/{sid}/log` 接口时我按**优先级从高到低判断**：①管理员→放行②本人（user_id 相等）→放行③题目 problems.public_cases>0→所有已登录用户放行；否则→403。审计记录策略：200/403 都写 audit_logs（status 列=200/403），但 401 未登录、404 不存在、400 参数错误**不写**——避免被暴力刷库。

### 🟠 Q3：为什么首页要「异步轮询模式」而不是同步？
> **答**：文档要求的 POST /api/submissions 必须「立即返回 pending + submission_id，然后通过 GET 详情轮询拿结果」。好处有两个：①防止浏览器网关超时（比如一道题 10 秒同步等会 504），②前端可以显示 Pending 状态给用户心理预期（有个进度感）。另外我做了兼容：用户改了自定义用例/内存/时间限制的情况下**自动 fallback 回旧同步 /api/judge**，不让老用户的功能回退。

### 🟠 Q4：SQLite 的幂等迁移怎么实现的？（为什么要 3 套 try/except PRAGMA？）
> **答**：因为 SQLite < 3.35 版本不支持 `ALTER TABLE ADD COLUMN IF NOT EXISTS` 语法，直接写会报错。我对每一列需要补的（audit_logs.status / submissions.language / submissions.score）都写了**同款 3 套保护**：①先试 `ALTER ... IF NOT EXISTS`（新版成功）②如果抛异常，就 `PRAGMA table_info` 查列名，③判断列确实不存在才执行普通 ALTER。这样新旧 SQLite 版本、新旧数据库都能兼容，不会启动就崩。

### 🟠 Q5：为什么 GET /api/problems 你要拆成两个接口？（2字段 vs 7字段）
> **答**：因为文档要求的公共接口 `GET /api/problems` **严格只能返回 id 和 title 两个字段**（smoke 脚本 T6.2 就是断言每个元素 keys==2），但是我的 problems.html 管理页要显示 difficulty/tags/time_limit/public_cases 等 7 个字段才能渲染卡片和👁🚫按钮。如果只改前端条件判断会违反 AC-R10。所以我**新增了 /internal/problems-list-full 内部路径**（登录后返回≥7字段）——双赢：公共接口严格符合文档2字段要求，管理页拿得到全量字段。

### 🟡 Q6：429 限流具体怎么实现？为什么不用 Redis？
> **答**：用最简单高效的**内存 dict 实现 60 秒滑窗**：`_rate_limit[user_id] = [t1, t2, t3...]`。每次提交：①清理 60 秒以前的时间戳 ②检查 len≤3 才放行 ③否则返回 429。不用 Redis 是因为单机单进程 FastAPI（uvicorn 默认 1 worker）内存 dict 已经够用、减少依赖安装复杂度；如果以后要多 worker 部署可以换 Redis，接口层不用改。

### 🟡 Q7：@require_login 装饰器 422 那个 BUG，为什么 FastAPI 会校验 viewer 参数？
> **答**：这是 FastAPI 基于类型签名的**自动校验机制**。如果路由函数的参数「既不是路径参数、又没有默认值、又没声明 Request 类型」，FastAPI 就把它当成必填 query 参数去校验。原写法 `fn(user, *args, **kwargs)` 把 viewer 当第一个位置参数传，相当于 viewer 没默认值了→校验缺失报 422。改成 kwargs 注入 + viewer=None 默认值后，FastAPI 就把它当作有默认值的可选参数，不再校验了。

### 🟡 Q8：错误信息脱敏具体哪 3 层？为什么要这样做？
> **答**：3 层正则：①Windows 绝对路径 `[A-Z]:\\...` → `<server>` ②Linux 绝对路径 `/home/...` → `<server>` ③Traceback 整段从开头到 File 行 → `<error>`。**为什么要脱敏？** 因为如果让用户看到 C:\Users\m1994\... 这种真实路径，可能被社工出真实用户名、目录结构、甚至找到其他漏洞入口；error 信息只需要告诉用户「语法错在第 X 行」这种有用的，不应该暴露服务器内部结构——符合 NFR5 安全要求。

### 🟢 Q9：submissions.html 这张新页面你怎么保证风格一致的？
> **答**：我拿 problems.html 和 users.html 作为模板直接复用：①banner 同结构 💻OJ调试平台+角色badge+admin文字+登出；②nav-cards 4 张顺序（🏠📋👥📝）复制粘贴；③筛选搜索框跟 users/problems 的 UI 一致，status pill 组我在 style.css 追加了统一的 9 色 active 样式；④sub-table 的 th/td/hover 背景色跟 users/problems 的表格取同款配色；⑤详情 Modal 里的 case-table 颜色（input蓝/expected绿/actual红）跟首页 result 区同款。整体看起来就是一套系统出来的，不是拼起来的。

### 🟢 Q10：以后如果要加 C++/Go 的判题支持要改哪些地方？
> **答**：**不需要改框架**，只要两步：①在系统里登录管理员账号，`POST /api/languages` 注册新语言（字段名 name/file_ext/compile_cmd/run_cmd/default_time_limit/default_memory_limit）——languages 表已经 8 字段结构完整，能存编译命令和运行命令；②判题引擎 Judger.judge 里已经根据 submission.language 去 languages 表拿对应的 compile/run 命令去执行（抽象层已扩展）。剩下的就是在运行环境里装 GCC/Go 编译器就行。接口层、前端层、权限审计层**0 修改**，扩展性非常好。

## 六、v3 追加评委高频 QA（4 题）

### 🟠 Q11：如果同一用户属于两个班级，同时给两个班级发了同一份作业，你会怎么去重？
> **答**：`audience_to_user_ids` 函数用了 Python set 做去重：先展开 `audience_classes → class_members JOIN → list[user_ids]`，再 union `audience_extra_users`，最后 `list(set(...))` 去重返回，矩阵 matrix 永远一行一位用户，不会一个人出现两行。

### 🟠 Q12：作业和考试的 URL 参数（judge?assignment_id=X vs judge?exam_id=Y）会不会冲突？
> **答**：不会。judge.html 顶部注入两个 JS 全局 `ASSIGNMENT_CTX / EXAM_CTX`：query 传了哪个就非空，另一个为 null。POST /api/submissions 同时允许传两列 `assignment_id/exam_id`（INTEGER DEFAULT NULL），SQLite 用单独列而非 enum，完全正交；后端 S4 校验：若 exam_id 非空→按考试权限 403，若 assignment_id 非空→按作业权限 403，最后才是普通提交。

### 🟡 Q13：考试倒计时横幅是前端 tick 还是后端每秒校验？
> **答**：**前端主导 + 后端兜底**。启动考试时后端返回 `{started: true, ends_at: ISO-8601}`，前端用 `Date.parse(ends_at) - Date.now()` 计算剩余毫秒，`setInterval 1s` tick 一次更新 HH:MM:SS；**每秒计算而非减1**（防止页面切后台 setTimeout 冻结）。后端在 POST /submissions 时还会再查一次 ends_at：过期 → 403 "考试已结束"。双保险。

### 🟡 Q14：班级删除时会不会把关联作业/考试也删了？
> **答**：只删 class_members（CASCADE 外键自动清理），**作业/考试保留**（因为 assignments.exam_id 不存在 CASCADE 约束）。删班级是管理员主动操作，关联的作业考试如果删了会导致历史 submissions 查询不到上下文，所以只断成员关系。符合真实教学场景：班级撤销，但已发布的作业/考试记录要留档。
